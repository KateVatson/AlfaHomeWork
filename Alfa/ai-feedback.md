# Обратная связь по архитектуре проекта

## Кратко
Отдельные задания сделаны хорошо (POM, BDD, DTO, Allure). Главный долг — организация репозитория: всё в одном модуле, тесты без пакетов, артефакты в src, нет CI и README.

## Хорошо
- **POM**: `hw19/act2/pages` — чейнинг и разделение страниц; контраст с `act1` нагляден.
- **API + DTO**: `hw17` — `Usuario`, REST Assured, Faker, порядок тестов.
- **Cucumber**: `hw16` — feature/steps/hooks, теги, DataTable, Scenario Outline.
- **Allure**: `hw20` — `@Step`, вложения, метаданные.
- **Слои**: `delivery` (model/service/app), `airport` (+ пакет exceptions, базовое исключение).
- **Тесты**: AAA-паттерн, осмысленные сообщения в assert.

## Проблемы
1. **Тесты вне пакетов** — `HomeWork1..32` в корне `src/test/java` (default package).
2. **Один модуль на всё** — Selenide, Allure, Cucumber, REST Assured сразу везде.
3. **Артефакты в src** — `hw16/*.png` в `main/java`, скриншоты `hw20/screenshots` в `test/java`.
4. **Вывод из модели** — `Parcel.printInfo()`, `System.out` в бизнес-логике `BaggageDropDesk`.
5. **Hidden-логика** — магический `AE-404` и «пасхалки» в `BaggageDropDesk`.
6. **Модификаторы доступа** — `protected weight`, package-private `trackingNumber` без причины.
7. **Зависимость от порядка** — `hw17` на статических полях; сетевые тесты не изолированы.
8. **Нет CI, README, AGENTS.md, тегов unit/integration.**

## Рекомендации
- Разложить тесты по пакетам: `basics/`, `oop/hw14-15`, `api/hw17`, `ui/hw19`, `bdd/hw16`, `reporting/hw20`.
- Идеально — разбить на Gradle-модули по темам.
- Разделить unit/integration через теги и `tasks.test { useJUnitPlatform { excludeTags(...) } }`.
- PNG и скриншоты — в `build/`, добавить в `.gitignore`.
- Убрать вывод/представление из доменных моделей (отдельный printer).
- Добавить README и CI-workflow.
